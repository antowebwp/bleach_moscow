# Перенос прототипа в WordPress и сохранение SEO

## Разметка и ACF
- Оставить существующие шаблоны home.php и uslugi.php, поля и данные ACF. Новый интерфейс подключать к их данным, не удаляя повторители и записи.
- Каталог: направление, заголовок, описание, изображение, список работ, ссылки. Списки выводить через PHP как native details/summary. ui.js добавляет анимацию; текст доступен без JS и присутствует в HTML.
- Страница FULL: название, описание, цена, состав ухода, материалы и галерея — серверный вывод ACF. Цена не должна оставаться захардкоженной.
- Общие контакты и футер переносить из shared-footer.html в footer.php; значения брать из существующих общих полей/Options, не дублировать на страницах.
- Изображения выводить через wp_get_attachment_image с alt, width/height, srcset/sizes и draggable="false". Для главного фото не применять lazy loading. Экранировать текст esc_html, ссылки esc_url, разрешённый редакторский HTML wp_kses_post.
- Подключать стили и скрипты через wp_enqueue_style/wp_enqueue_script, с зависимостями и версиями. ui.js общий, анимации каждой страницы отдельные. Оставить Contact Form 7 и его обработчики.
- Инициализация раскрытий основана на разметке details, а не на фиксированном количестве услуг. Эксклюзивные группы задаются атрибутом name. После завершения перехода пересчитывается ScrollTrigger.

## SEO: обязательная проверка при переносе
- Сохранить существующие публичные URL, регистр, слуги и завершающие слеши. HTML-адреса прототипа не являются новыми адресами продакшена. FULL остаётся /chistka_obuvi_full/.
- Сохранить wp_head() и wp_footer(): они присутствуют в исходной теме и нужны для хуков плагинов. Не добавлять второй комплект title, canonical, robots, Open Graph или JSON-LD поверх SEO-плагина.
- Сохранить базу данных и SEO-метаданные страниц, настройки плагина, sitemap, robots.txt, редиректы и микроразметку. Наличие этих данных нельзя проверить по одной папке темы.
- Сохранить важный индексируемый контент, один H1 на странице, логичную иерархию заголовков, внутренние ссылки, alt изображений. Текст ACF должен находиться в исходном HTML, не загружаться только по клику.
- До переноса снять базовый crawl сайта: URL, статусы, title/description, canonical, robots, заголовки, внутренние ссылки и schema. После переноса сравнить результат; ошибки 404, новые noindex и дубли canonical блокируют релиз.
- Проверить мобильный интерфейс, скорость загрузки и отсутствие сдвигов макета. Анимации не должны мешать чтению, навигации и reduced motion.

Прототип не изменяет исходную тему или SEO-настройки действующего сайта. Паритет SEO подтверждается сравнением до/после на установленном WordPress, а не наличием похожего дизайна.

## Каталог брендов и кейсы
- Сохранить страницы и slug действующих кейсов; `/cases/*.html` — только адреса локального прототипа, их нельзя переносить в продакшен как замену старым URL.
- Каталог соответствует `brands.php`: сохранить `brand_cards`, `brand_card_title1`, `brand_card_title2`, `brand_card_href`, `brand_card_price`, `brand_card_img`, `brands-slider`/`brands-img`. Ссылки внутри прототипа исправлены; в WordPress получить их через связи с существующими страницами и get_permalink(), проверить прежние ошибочные значения вида http://chistka_ugg_ugg.
- Одиночный кейс соответствует `brand.php`: поля `brand_title`, `brand_name`, `brand_text`, `brand_img`, `brand_pricelist`, `brand_summary`, `brand_slider` остаются источником. Один общий PHP-шаблон создаёт отдельную страницу для каждого кейса.
- Для точных объяснений мастера можно добавить необязательные ACF-поля: состояние при поступлении, выбранный метод, почему выбран, ограничения результата. Не подменять реальные данные выдуманной историей; пустые поля не выводить.
- Страница кейса содержит один H1 (бренд + вид работы), описание и состав в исходном HTML, обычные ссылки из каталога и обратно. Вся карточка — ссылка на самостоятельную страницу; быстрый просмотр удалён. Единственным источником данных остаётся существующая запись.
- Сохранять title/description/canonical/schema существующего SEO-плагина и старые URL. Не плодить индексируемые копии по состояниям фильтров. До изменения стратегии URL и индексации выполнить SEO-аудит; отдельный URL сам по себе не гарантирует продвижение.
- Оригинальные фотографии сейчас сохранены для прототипа. На WordPress использовать responsive sizes/srcset и оптимизированные размеры вложений, lazy loading карточек ниже первого экрана; не отдавать все полноразмерные оригиналы сразу.
- До релиза проверить поиск, комбинации фильтров, пустое состояние, появление информации при hover/focus, видимость подписей на touch, паузу бегущей строки, reduced motion и мобильную ширину.

## Повторяемая плитка каталога
- Цикл записей разбивается на группы по 10: project-pattern с data-size равным количеству карточек. Полный модуль занимает квадрат 4 × 4; первая и десятая плитки крупные (2 × 2), остальные — 1 × 1. Все размеры задаются CSS, отдельные ACF-поля для размера не нужны.
- Неполный последний модуль выводит обычные квадратные плитки в четыре колонки, без увеличения ради заполнения всего квадрата. После фильтрации brands.js заново собирает группы из видимых записей. На мобильном — две колонки с крупными первой и десятой карточками.
- Число работ выводить из количества записей; data-count-to содержит то же число. GSAP считает от 0 один раз при появлении. Для reduced motion и без JS остаётся итоговое число в HTML.
- Заголовок кейса, задачи и стоимость остаются исходным контентом. Декоративные линии и GSAP-появления не требуют дополнительных ACF-полей.
